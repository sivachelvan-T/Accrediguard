# Render Free Deployment — Persistent Demo Data

This version deploys the React frontend and Express backend as one Render Web Service and uses a Render Postgres database for persistent relational data. Uploaded PDFs are also stored in Postgres as `BYTEA`, so the app does not depend on Render's ephemeral local filesystem for document retention.

## 1. Push the repository

The repository root must contain:

- `render.yaml`
- `backend/`
- `frontend/`

Do not commit `.env` files or real secrets.

## 2. Create the Render Blueprint

1. Open Render.
2. Choose **New + → Blueprint**.
3. Connect `sivachelvan-T/Accrediguard`.
4. Render reads `render.yaml` and creates:
   - `accrediguard-ai` — Free Web Service
   - `accrediguard-db` — Free Postgres
5. Apply the Blueprint.

The Free Postgres database is limited to 1 GB and, according to current Render policy, expires 30 days after creation. It can be upgraded before deletion if you need to keep the data longer.

## 3. Environment variables

The Blueprint supplies:

- `DATABASE_URL` from the Render Postgres connection string
- `USE_SQLITE=false`
- `NODE_VERSION=22.13.0`
- `NODE_ENV=production`
- `JWT_SECRET` generated by Render
- `JWT_EXPIRES_IN=8h`
- `FRONTEND_URL=https://accrediguard-ai.onrender.com`
- `MAX_FILE_SIZE_MB=10`
- `MAX_FILES_PER_REQUEST=5`
- `UPLOAD_DIR=./uploads`

If Render gives the service a different URL, update `FRONTEND_URL` to that exact URL.

## 4. Build and start

Build command:

```text
npm install --prefix backend && npm install --include=dev --prefix frontend && npm run build --prefix frontend && test -f frontend/dist/index.html
```

Start command:

```text
npm run seed --prefix backend && npm start --prefix backend
```

The seed script is idempotent. It creates demo data only when the database is empty. It does **not** erase user-created data on normal restarts or redeploys.

## 5. What persists

The Postgres database stores:

- Users and roles
- Departments
- Accreditation frameworks
- C1–C10 criteria
- Projects
- Student memberships
- Faculty assignments
- Documents and document versions
- PDF bytes
- Extracted pages
- AI analysis results
- Evidence
- Faculty reviews
- Notifications
- Audit logs

Therefore logging out and back in, a normal service restart, or a new application deployment will not reset those records.

## 6. Student → Faculty workflow

1. Student creates a project.
2. Student selects the appropriate accreditation framework.
3. Student selects the corresponding Faculty Reviewer.
4. Student uploads the PDF.
5. AccrediGuard performs the analysis.
6. Student explicitly clicks **Submit Project for Faculty Verification**.
7. Project changes to `UNDER_REVIEW`.
8. Assigned faculty reviews C1–C10 evidence.
9. Faculty can approve, partially approve, reject, or request revision.
10. A revision request changes the project to `REVISION_REQUIRED`.
11. Student uploads the revised document and submits again.

## 7. Super Admin faculty creation

Super Admin → **Users** → **Create Account**.

The Super Admin enters:

- Faculty name
- Faculty email
- Password
- Department

The new faculty account immediately becomes available in the Student's **Faculty Reviewer** selection list.

## 8. Important Render limitation

The Free Web Service filesystem is still ephemeral. This version deliberately avoids depending on it for application data: the database and uploaded PDF bytes are stored in Postgres. Temporary upload files may disappear after a restart, but the stored database records and PDF bytes remain available while the Postgres database itself remains active.

Current Render policy says Free Postgres databases expire after 30 days. If you need the data beyond that period, upgrade/export the database before the expiration and grace period ends.


## Production configuration in this package

The included `render.yaml` is configured for a single Render Web Service plus Render PostgreSQL:
- PostgreSQL is forced with `USE_SQLITE=false`.
- `DATABASE_URL` is injected from the Render database connection string.
- `JWT_SECRET` is generated by Render.
- The React build is served by the same Node service, so the frontend uses the same-origin `/api` path.
- The start command runs the idempotent demo seed before starting the API. The seed exits without changing existing data when users already exist.

Demo accounts created by the seed use password `Demo@1234`:
- `admin@accrediguard.demo` — SUPER_ADMIN
- `accreditation@accrediguard.demo` — ACCREDITATION_ADMIN
- `faculty@accrediguard.demo` — FACULTY_REVIEWER
- `coordinator@accrediguard.demo` — PROJECT_COORDINATOR
- `student@accrediguard.demo` — STUDENT
- `auditor@accrediguard.demo` — VIEWER

Do not commit a real `.env` file or database credentials.
